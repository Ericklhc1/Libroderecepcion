## Reversión y compuerta operativa

Al no cambiar schema, migraciones ni servicios, una reversión de código a la versión anterior no requiere deshacer datos ni restaurar una base. Las preferencias nuevas se pueden ignorar y `candidateIds` mantiene el formato anterior. **Nunca restaurar una copia antigua de la base para revertir este bloque**, pues perdería trabajo registrado después.

Aun así, debe acreditarse compatibilidad de sesiones/formularios abiertos entre despliegues de Next.js y la configuración efectiva de Skew Protection. Un rollback de código no prueba esa compatibilidad. Si no se puede verificar el estado de formularios, la continuidad operativa, el cierre o el comportamiento del despliegue, mantener producción actual.

Antes de publicar: SHA final, lint/tipos/suite/build/recorridos verdes; revisión de los cambios; main sin divergencias; cero consumo adicional confirmado; configuración de despliegue y reversión verificadas. Después de una publicación autorizada: commit/versión servidos, CI exacta, estado READY y lectura de salud. No hacer pruebas de escritura en producción.
